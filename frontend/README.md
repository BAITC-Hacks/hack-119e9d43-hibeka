# Фронтенд «Граф денег»

React + TypeScript + Vite + Cytoscape. Две основные области: очередь проверки
и карточка выбранного клиента с локальным графом. Приложение использует реальный
FastAPI и автоматически открывает последний завершённый анализ.

## Локальный запуск

Нужен Node.js 22.13+ из ветки 22 или Node.js 24+.
Из корня репозитория запустите бэкенд:

```bash
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале:

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
```

Откройте http://127.0.0.1:5173. Vite проксирует `/api` на порт 8000.
Если готовых результатов нет, загрузите три файла Parquet через интерфейс
или выполните анализ по инструкции в корневом README.

## Возможности

- Выбор готового анализа, сводка количества клиентов, связей, переводов и суммы.
- Очередь с глобальными местами, по 30 клиентов на страницу.
- Выбранная карточка сохраняется при переходе между страницами, включая
  автоматически выбранного первого клиента. Если строка вне текущей страницы,
  интерфейс показывает пояснение. При изменении фильтров выбирается первый
  клиент новой выдачи; пустая выдача очищает выбор.
- Точный поиск полного идентификатора во всём выбранном анализе.
- Поиск запускается по Enter или кнопке; внешние пробелы удаляются. Редактирование
  и очистка отменяют старый запрос и сбрасывают страницу. Несовместимые с найденным
  клиентом фильтры снимаются с уведомлением, совместимые сохраняются. В общей
  очереди открывается страница глобального ранга найденного клиента.
- Фильтры роли, группы, исходных клиентов и границы выборки.
- Карточка: объяснение роли простыми словами, входящие/исходящие суммы,
  ограничения наблюдения, полные таблицы контрагентов и детали расчётов.
- Суммы в таблицах отображаются в KZT с двумя знаками после запятой.
  Общий компонент копирования сообщает об успехе только после записи в буфер;
  при отказе или недоступности Clipboard API показывает понятную ошибку.
- Направленный локальный граф одного шага, максимум 150 узлов. Выбор узла
  открывает его карточку. Масштаб, вписывание графа, цвета ролей/групп,
  обозначение исходных клиентов и границы выборки. Увеличенная легенда находится
  внутри рамки графа и не перекрывает узлы. Масштаб меняется колёсиком или кнопками;
  100% соответствует вписанному графу, кнопка «Вписать граф» возвращает этот вид.
  По умолчанию видны до 20
  контрагентов по серверному приоритету и выбранный клиент; кнопка показывает
  всех загруженных контрагентов. Фильтр направления применяется до ограничения
  числа узлов. В режиме «Все связи» сохранены связи между видимыми соседями,
  в режимах направлений — только соответствующие стрелки выбранного клиента.
  Счётчик не включает выбранного клиента; ограничения ответа API подписаны отдельно.
  Развёрнутый просмотр открывается в модальном окне, закрывается кнопкой или Esc.
  Выбор стрелки или пункта списка показывает точные идентификаторы сторон,
  сумму и число переводов. Это операции отображения, они не меняют аналитику.
- Обзор групп в раскрывающемся блоке; переход к группе и её ведущим клиентам.
- Загрузка трёх файлов, фоновый анализ, опрос статуса и сообщение об ошибке.
  Закрытие окна не отменяет запущенную серверную обработку; повторное открытие
  кнопки статуса продолжает наблюдение.
- Скачивание `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv` конкретного анализа.

Идентификаторы всегда строки. Роли, порядок и оценки приходят с сервера;
браузер не пересчитывает аналитические формулы. При смене анализа или клиента
предыдущие запросы отменяются, а ответы дополнительно привязаны к ключу запроса
и `run_id`. Ошибка API не подменяется демонстрационными данными.

Состояние выбора, фильтров, страницы и поиска текущего интерфейса находится
в `src/state/review.ts`. Редьюсер не хранит серверные ответы: их получает
`useResource`. Старые ответы поиска защищены отменой через `RequestGate` и
версией поискового запроса. Очередь проверяет ключ страницы/фильтров перед
автоматическим выбором клиента. URL-состояние не используется.

Контракт HTTP и адаптер: `src/api/client.ts`. Исходные mock-модули и их тесты
первого этапа сохранены, но основное приложение их не импортирует.
`VITE_API_MODE` и `VITE_MOCK_SCENARIO` не управляют рабочим приложением.

## Сборка

```bash
npm --prefix frontend run build
```

Команда проверяет TypeScript и создаёт `frontend/dist`. Граф загружается
отдельным JS-модулем. Для локального просмотра сборки при запущенном бэкенде:

```bash
npm --prefix frontend run preview
```

Адрес preview: http://127.0.0.1:4173. Для публикации `dist` нужен сервер,
проксирующий `/api` в FastAPI; статический хостинг без прокси недостаточен.

## Проверки по запросу

```bash
npm --prefix frontend run lint
npm --prefix frontend run format:check
npm --prefix frontend test
```

`tests/review.test.ts` проверяет состояние текущего интерфейса и реальный
HTTP-адаптер с контролируемыми ответами: сохранение выбора, фильтры, пагинацию,
запоздавший поиск, ошибки сервера, точность gid и денежный формат. Тесты старого
mock-адаптера также сохранены. Отдельного компонентного/e2e-фреймворка нет.

Ручная проверка с работающим FastAPI: перейти на следующую страницу и убедиться,
что карточка не меняется; найти gid с пробелами по Enter; найти клиента вне
фильтра и проверить уведомление; очистить запрос; открыть контрагента; скопировать
gid. Неизвестный gid должен показать ошибку без замены открытой карточки.

Если после обновления проекта отсутствует Cytoscape, повторите `npm ci`.
При изменении `vite.config.ts` перезапустите dev-сервер. Если `/api` возвращает
HTML вместо JSON, проверьте запущенный бэкенд и настройку прокси: приложение
показывает эту причину вместо технической ошибки JSON.

## ИИ-аналитик

Боковая панель вызывается из шапки. Доступна вся выбранная выборка, выбранный
клиент передаётся как контекст вопроса. Ключ задаётся в корневом серверном `.env`;
браузер отправляет запрос только в собственный FastAPI. Настройка описана
в корневом README.

Ответы содержат ссылки на подтверждённые сервером ID и раскрываемые источники.
Markdown отображается без HTML, внешних картинок и произвольных ссылок.
Чат отдельный для каждого анализа. История живёт в памяти до перезагрузки;
для следующего запроса передаются последние восемь сообщений, каждое до 5500
символов. Есть отмена, повтор, очистка и сообщение об отсутствии ключа.
При смене анализа предыдущий запрос отменяется; ответы проверяются по `run_id`.
