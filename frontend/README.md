# Фронтенд «Граф денег» — этапы 1–2

Адаптивное рабочее пространство: сводка, очередь проверки, точный поиск по gid,
фильтры роли и кластера, карточка клиента, отправители/получатели и компактная
таблица кластеров. Все точки выбора используют одно состояние клиента.

## Запуск

Нужен Node.js 22 (от 22.13) или 24+ и npm. Из корня репозитория:

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
```

Адрес: http://127.0.0.1:5173. Production-сборка и её просмотр:

```bash
npm --prefix frontend run build
npm --prefix frontend run preview
```

Стандартный адрес preview: http://127.0.0.1:4173.

## Источник данных и границы

Требования: приложенное «ТЗ разработки» v1.1, разделы 7 и 14, и фронтенд-ТЗ
из переписки. Обязательные фильтры П0 — роль и кластер; seed, граница и диапазон
приоритета относятся к П1. Признаки seed и границы видны в карточке.

В этой копии репозитория аналитический HTTP API отсутствует. Существующий
изолированный mock-адаптер расширен до 63 синтетических клиентов, чтобы проверять
три страницы очереди и переходы между связанными клиентами. Суммы, роли, рейтинг,
объяснения, кластеры и время расчёта **не получены из реального датасета**.
Демонстрационный режим явно обозначен в интерфейсе. Python starter и Parquet
не изменены и не включены в браузерную сборку.

React + TypeScript + Vite, обычный CSS и токены первого этапа сохранены.
Новые зависимости не добавлены. Макетов и AGENTS.md в проекте нет.

## Состояние и взаимодействия

- `src/state/workspace.ts`: один `WorkspaceController` на экземпляр API;
  React подписывается через `useSyncExternalStore`. Единственный `selectedGid`
  используется очередью, карточкой и областью будущего графа. Компоненты не
  копируют ответы API в собственные состояния.
- Очередь получает одну страницу через `offset/limit`, размер — 25. Параметры
  централизованы в `src/api/queries.ts`; фильтрация mock выполняется адаптером,
  не компонентом. Глобальные ранг и оценки при фильтрации не пересчитываются.
- Смена страницы и повторная загрузка сохраняют выбор, даже если выбранная
  строка больше не входит в выдачу. Несуществующая страница после сокращения
  результата заменяется последней доступной.
- Явное изменение фильтров сбрасывает страницу и выбирает первого доступного
  клиента; при пустом результате очищает карточку. Это правило раздела 14.5 ТЗ.
- Поиск — точное совпадение полного gid во всём наборе, по Enter или кнопке.
  Запросы при каждом нажатии клавиши не отправляются. Внешние пробелы удаляются,
  пустой/невалидный запрос не отправляется. Редактирование сбрасывает страницу.
  Неуспешный поиск оставляет прежнюю карточку и показывает понятную ошибку.
- Поиск и переход из контрагентов/главных клиентов кластера открывают страницу
  глобального ранга найденного клиента. Активные фильтры снимаются с пояснением.
  Это согласованное упрощение: API не предоставляет позицию клиента внутри
  отфильтрованной выдачи; фронтенд не скачивает все страницы для её вычисления.
- `RequestGate` отменяет предыдущие запросы и проверяет актуальность ответа,
  даже если адаптер проигнорировал AbortSignal. Очередь, карточка, поиск и кластеры
  имеют отдельные каналы. При смене клиента старые данные сразу убираются.
  Проверяются `run_id`, точный gid, уникальность строк и корректность ранга.
- Внешней библиотеки кеширования в проекте нет. Повторный выбор уже открытого
  клиента не вызывает запрос; кнопки обновления загружают актуальный ответ.
- Роутер и URL-состояние отсутствовали на первом этапе. На втором они не
  добавлены: после перезагрузки выбирается первый клиент последнего завершённого
  запуска. Прямые ссылки на карточки и история выбора пока не поддерживаются.
- Контрагенты приходят полными списками в карточке согласно ТЗ. Таблицы имеют
  собственную прокручиваемую область; их строки не обрезаются лимитом графа.
- `CopyGidButton` использует Clipboard API, не выбирает строку при копировании,
  сообщает об успехе только после завершения записи и показывает ошибку при
  отказе браузера. Для Clipboard API нужен localhost либо HTTPS.

## Контракт интеграции

Типы: `src/types/api.ts`. Во всём пути gid — десятичная строка (до 19 цифр),
никогда не JavaScript Number. Nullable-метрики отображаются как «Нет данных».

| Метод адаптера                    | Планируемый endpoint                 | Результат                                                                              |
| --------------------------------- | ------------------------------------ | -------------------------------------------------------------------------------------- |
| `listRuns(signal)`                | `GET /api/runs`                      | `Run[]`; выбирается последний завершённый запуск                                       |
| `listNodes(runId, query, signal)` | `GET /api/runs/{run_id}/nodes`       | `NodePage`: `run_id`, `items`, `total`; `offset`, `limit`, `role`, `cluster_id`        |
| `getNode(runId, gid, signal)`     | `GET /api/runs/{run_id}/nodes/{gid}` | `ClientDetails`, включая метрики, объяснения, пять факторов и обе таблицы контрагентов |
| `listClusters(runId, signal)`     | `GET /api/runs/{run_id}/clusters`    | `ClusterResponse`: `run_id`, `items`; `top_gids` как массив строк                      |

`RunSummary` и `priority_reason_short` остаются предложенной формой контракта
первого этапа для согласования с FastAPI. `rank` карточки — глобальный ранг
в той же сортировке, что общая очередь. Неизвестный клиент — ошибка 404.
Типы будущего графа сохранены, его запросы на этом этапе не реализованы.

HTTP-адаптер подключается через `src/api/index.ts`. Компоненты не импортируют
fixtures и не вызывают fetch напрямую. Vite проксирует `/api` на
http://127.0.0.1:8000. Режим `http` пока явно сообщает о неподключённом API:
скрытого переключения на mock нет. Health, HTTP, загрузка, polling и CSV — этап 4.

## Проверка состояний

В полосе «Демонстрационные данные» доступны состояния:

| Сценарий      | Результат                                           |
| ------------- | --------------------------------------------------- |
| `success`     | Полный результат, 63 клиента и три страницы         |
| `loading`     | Загрузка до переключения сценария                   |
| `empty`       | Нет готового запуска                                |
| `error`       | Ошибка загрузки запуска                             |
| `queue-error` | Ошибка очереди при доступной сводке                 |
| `card-error`  | Очередь работает, карточка показывает ошибку        |
| `partial`     | Nullable-метрики, отсутствующие объяснения и вклады |

Повтор в сценарии ошибки намеренно повторяет её; для восстановления выбрать
«Готовый результат». Начальное состояние задаётся в `.env.local` по `.env.example`:

```text
VITE_API_MODE=mock
VITE_MOCK_SCENARIO=success
```

Неизвестный сценарий использует success; неизвестный режим API блокирует данные.

## Проверки

```bash
npm --prefix frontend run format:check
npm --prefix frontend run lint
npm --prefix frontend run typecheck
npm --prefix frontend test
npm --prefix frontend run build
```

Используется существующий встроенный Node test runner. Тесты проверяют обзор,
пагинацию, фильтры, поиск, единый выбор, обновление, ответы в обратном порядке,
отмену, ошибки, неполные данные, строковые gid, копирование и форматирование.
Отдельного компонентного/e2e-фреймворка в проекте нет.

Ручной сценарий: открыть очередь, перейти на страницы 2/3, применить роль и
кластер, проверить пустое пересечение и сброс. Найти `900000000000000107`
(изолированный seed) и неизвестный `123`. Открыть `900000000000000101`, затем
его получателя `900000000000000102`, проверить синхронный выбор и новые суммы.
Выбрать top_gid из раскрываемой таблицы кластеров. Быстро переключить клиентов,
обновить данные, скопировать gid из карточки и невыбранной строки. Проверить
семь демонстрационных состояний и клавиатурные Enter, Tab, Space.

Проверять 320/375/768/1440 px, раскрытые таблицы и отсутствие переполнения всей
страницы. Внутренние области таблиц прокручиваются; кнопки имеют видимый фокус,
состояния и подтверждения доступны через ARIA. Анимации учитывают reduced motion.
