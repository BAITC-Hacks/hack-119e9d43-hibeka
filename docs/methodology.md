# Методика анализа, версия 1.1

## Что означает результат

Роли — гипотезы о наблюдаемой функции клиента. Оценка роли — сила признаков,
а не вероятность виновности. Приоритет — очередь для дополнительной проверки.
Без независимых меток accuracy, precision и recall не оценивались.

## Данные и признаки

Сначала проверяются все три Parquet, включая точные пары, количества операций
и суммы с абсолютным допуском 0,01 KZT. Идентификаторы — Python int, в JSON —
строки. Одинаковые строки операций сохраняются. Денежные агрегаты складываются
в тиынах, округление ROUND_HALF_UP до двух знаков.

Граф содержит всех клиентов, включая изолированных. PageRank взвешен по
суммам: alpha=0,85, max_iter=1000, tol=1e-8. При несходимости расчёт завершается
ошибкой. Посредничество точное, нормализованное, по направленным кратчайшим
путям без весов расстояния. Суммы не являются длинами путей.

Для Louvain встречные суммы складываются в неориентированной проекции,
resolution=1, seed=42. Узлы и рёбра сортируются по числовым gid. Номера групп
идут по убыванию размера, при равенстве — по минимальному gid. Компонента
связности и кластер — разные признаки. Каждый изолят имеет свой кластер.

`n_seed_upstream` — число различных исходных клиентов, из которых узел
достижим по направленным путям. Обход с множеством посещённых узлов исключает
зацикливание и повторный счёт; сам seed не засчитывается себе даже в цикле.
`seed_in_direct` — число непосредственных отправителей-seed.
Это структурная связь, которая не доказывает движение одних и тех же денег.

`first_in_date` — первая дата входящего перевода, `days_after_first_in` —
число дней до последней даты всего набора. Без входящих даты отсутствуют.
Время суток не известно, порядок операций одного дня не устанавливается.
`truncated_by_depth` означает depth=4 без исходящих. Для seed входящие особенно
неполны. У всех клиентов разность входа и выхода не является остатком на счёте.

## Процентили

P(x) считается среди положительных значений у неизолированных клиентов:
`(число меньших + 0,5 × число равных) / число положительных`.
Для нуля, отсутствующего значения, изолята или пустой группы P=0.
Одинаковые положительные значения дают P=0,5. Показатели не пересчитываются
от фильтров интерфейса. `activity_kzt=in_kzt+out_kzt` — активность, не уникальные деньги.
`neighbor_count=in_deg+out_deg` учитывает встречного контрагента дважды.

## Роли: условия и сила признаков

Все параметры закреплены в `config.json`. Далее приведены значения по умолчанию.
`clip` ограничивает число диапазоном 0..1. Оценка выбранной роли равна `q×clip(S)`.

| Роль | Условия | S | q |
|---|---|---|---|
| consolidator | in_deg≥3 | .45×min(in_deg/8,1)+.25×P(in_kzt)+.20×P(in_tx)+.10×min(seed_up/3,1) | .90; на границе .60 |
| distributor | out_deg≥10 | .50×min(out_deg/20,1)+.30×P(out_kzt)+.20×P(out_tx) | .90 |
| transit | не seed; depth<4; есть вход и выход; .8≤r=out/in≤1.2 | .60×clip(1−abs(r−1)/.2)+.20×min(min(in_tx,out_tx)/3,1)+.20×min(min(in_kzt,out_kzt)/100000,1) | .75 |
| terminal | не seed; depth<4; есть вход, нет выхода | .60+.40×clip(days_after_first_in/7) | .65 |
| coordinator | есть вход и выход; betweenness>0 и ≥95-го процентиля положительных значений (linear); соседних кластеров≥2 | .50×P(betweenness)+.30×min(neighbor_cluster_count/3,1)+.20×min(seed_up/3,1) | .80 |
| peripheral | ни одно правило не выполнено | 0 | 0 |

Основная роль выбирается **до** вычисления оценки:

1. coordinator;
2. при пересечении consolidator/distributor сравниваются in_deg/3 и out_deg/10;
   равенство разрешается в пользу consolidator;
3. consolidator, затем distributor, затем transit, затем terminal;
4. иначе peripheral.

Изменение q не влияет на выбор роли или приоритет. Все кандидатные роли,
правило выбора, S, q и полные объяснения сохраняются в `analysis.json`.
Сводка распределений и примеры каждого пересечения — в `role_diagnostics.json`.
Peripheral не означает отсутствие риска. Coordinator — структурный связующий
узел, а не доказанный организатор. Transit не доказывает быстрый перевод;
terminal — отсутствие исходящих только в наблюдаемой выборке.

## Приоритет

`priority=.30×P(betweenness)+.20×P(pagerank)+.20×P(activity_kzt)
          +.15×min(n_seed_upstream/3,1)+.15×P(neighbor_count)`.

У изолятов оценка и все пять вкладов равны нулю, независимо от PageRank.
Seed сам по себе баллов не добавляет. Роль и role_score в рейтинг не входят.
Сортировка: priority, округлённый до 12 знаков, по убыванию; затем точный gid
по возрастанию. Экспортируется исходный score, ранг определяется указанным правилом.
Все пять raw/normalized/weight/contribution сохраняются для объяснения.

Веса — экспертная гипотеза, не обученная модель. `ranking_review.md` в каждом
снимке содержит фактический топ-20, сравнение с оборотом и все несовпадающие
узлы. `ranking_sensitivity.json` и отчёт содержат десять изменений весов ±20%
и пять исключений фактора с перенормировкой. Это исследование устойчивости,
не доказательство точности или преимущества над оборотом.

## Выгрузки и воспроизводимость

Схемы обязательных CSV совпадают с ТЗ; nullable-показатели остаются во
внутреннем `analysis.json`. Внутренний оборот кластера учитывает каждую
исходную направленную связь ровно один раз. `top_gids` — JSON-массив строковых
gid, отсортированный по глобальному рангу. Гипотезы основаны на составе ролей
и наблюдаемых потоках; кластеры не объявляются преступными группами.

Один pipeline сохраняет проверенные CSV, входной снимок, конфигурацию,
контрольные суммы, версии библиотек и длительности. Повторять с тем же кодом,
средой и конфигурацией. Для изменения порогов/весов обновите версию правил
в конфигурации и повторите проверку рейтинга. Текущий экспорт публикуется
через атомарный указатель `latest`; старый результат сохраняется при ошибке.

## Масштабирование

Текущая реализация рассчитана на предоставленный небольшой граф. Точное
посредничество и обходы от каждого seed могут стать узким местом на миллионе
узлов. Для такого масштаба понадобятся раздельная подготовка агрегатов,
хранение графа вне JSON, приближённые центральности с проверкой качества и
фоновая обработка. Результаты на текущих 2 248 узлах не доказывают такую масштабируемость.
